# 目的

systemverilogの文法を扱う。

## モジュールパラメータ

SystemVerilog の `parameter WIDTH = 8` は、

**モジュールの中で使える定数（パラメータ）を定義している部分**です。

このパラメータを使うことで、**ビット幅などを柔軟に変更できる設計**が可能になります。

---

## 🧩 意味の説明

```systemverilog
module adder #(
    parameter WIDTH = 8
)(
    input  logic [WIDTH-1:0] a,
    input  logic [WIDTH-1:0] b,
    output logic [WIDTH-1:0] sum,
    output logic              carry
);
```

この `parameter WIDTH = 8` は：

* モジュール `adder` の中で使う定数 `WIDTH` を定義しており、
* デフォルト値として `8` が設定されています。
* `WIDTH` は **信号のビット幅**を指定するのに使われています。

---

## 🔹 使われ方の具体例

ここで定義した `WIDTH` は、後の配列宣言 `[WIDTH-1:0]` に使われています。

```systemverilog
input  logic [WIDTH-1:0] a;  // 例: WIDTH=8 → a[7:0]
input  logic [WIDTH-1:0] b;  // 例: WIDTH=8 → b[7:0]
output logic [WIDTH-1:0] sum; // 例: WIDTH=8 → sum[7:0]
```

つまり、`WIDTH` が **ビット幅の指定子** として働いています。

これにより、1つのモジュール定義で「8ビット加算器」「16ビット加算器」「32ビット加算器」など、

さまざまなバージョンを再利用できます。

---

## 🔹 上書き（パラメータ上書き）する方法

モジュールをインスタンス化するときに、

このパラメータを変更することができます。

例：16ビット加算器にしたい場合👇

```systemverilog
adder #(.WIDTH(16)) u_adder16 (
    .a(a16),
    .b(b16),
    .sum(sum16),
    .carry(carry16)
);
```

このように書くと：

* `WIDTH = 16` と上書きされ、
* 信号は `logic [15:0]` の16ビット幅で処理されます。

---

## 🔹 もし parameter がなかったら？

たとえば下のように書いてしまうと：

```systemverilog
input logic [7:0] a, b;
output logic [7:0] sum;
```

→ この場合、「8ビット加算器」として**固定的**なモジュールになります。

後から16ビットや32ビット対応を作りたくなったら、新しいファイルを作り直す必要があります。

`parameter` を使えば、その手間が不要です。

---

## 🧠 まとめ

| 項目                   | 内容                                        |
| ---------------------- | ------------------------------------------- |
| **キーワード**   | `parameter`                               |
| **意味**         | モジュール内で使える定数を定義              |
| **用途**         | ビット幅や回数などの設定を柔軟に変更        |
| **デフォルト値** | `WIDTH = 8`→ 指定がなければ8ビット加算器 |
| **上書き例**     | `adder #(.WIDTH(16)) u_adder (...);`      |


## always_comb

SystemVerilog における **`always_comb`** は、

**「組み合わせ回路（combinational logic）」を表すための専用構文** です。

---

## 🧩 基本の意味

```systemverilog
always_comb begin
    product = a * b;
end
```

この部分は、

> 「入力 `a` や `b` が変化したら、すぐに出力 `product` を再計算する」
>
> という動作を意味します。

つまり：

* **順序を持たない** （クロックに依存しない）
* **常に最新の入力値に応じた出力を出す**

  という、**純粋な組み合わせ論理**を表現しています。

---

## 🔹 Verilog の古い書き方との違い

従来の Verilog では、同じ意味を次のように書いていました：

```verilog
always @(*) begin
    product = a * b;
end
```

`@(*)` は「感度リストにすべての入力信号を自動で含める」という意味です。

ただし、Verilog の場合は以下のような落とし穴がありました。

### ⚠ 問題点

* 感度リストを手動で書き忘れるミス（例：`always @(a)` など）
* ブロッキング／ノンブロッキング代入の混乱（`=` と `<=`）
* シミュレーション結果と合成結果の不一致

---

## 🔹 SystemVerilog の `always_comb` はそれを安全にした構文

SystemVerilog の `always_comb` は、

このような「組み合わせ回路」を安全に記述するために導入されたものです。

| 比較項目                     | `always @(*)`            | `always_comb`              |
| ---------------------------- | -------------------------- | ---------------------------- |
| 感度リスト                   | 自動生成（入力依存）       | 自動生成（より厳密）         |
| シミュレーション・合成の一致 | 一致しない場合がある       | 常に一致するよう保証         |
| 初期化タイミング             | 初回に実行されない場合あり | **初回から実行される** |
| 同一信号を複数ブロックで代入 | 可能（危険）               | **禁止される（安全）** |
| 推奨度                       | 古いVerilogとの互換用      | ✅ 現代の標準的な書き方      |

---

## 🔹 実際の動作イメージ

```systemverilog
always_comb begin
    product = a * b;
end
```

は、

次のような「常に入力を監視する自動更新ロジック」と考えられます👇

```
if (a or b changes)
    product ← a * b;
```

---

## 🔹 実際に使う場面

| 用途                       | ブロック名                                    | トリガー                   |
| -------------------------- | --------------------------------------------- | -------------------------- |
| 組み合わせ論理             | `always_comb`                               | 入力信号が変化したとき     |
| クロック同期（順序回路）   | `always_ff @(posedge clk)`                  | クロックの立ち上がり       |
| 非同期リセット含む同期回路 | `always_ff @(posedge clk or negedge rst_n)` | クロックまたはリセット     |
| 特殊なレベル感知イベント   | `always_latch`                              | ラッチ構造（通常は非推奨） |

---

## ✅ まとめ

| 項目                            | 内容                                       |
| ------------------------------- | ------------------------------------------ |
| **構文名**                | `always_comb`                            |
| **意味**                  | 組み合わせ回路を記述する（クロック非依存） |
| **動作**                  | 入力信号が変化するたびに中身を再評価       |
| **利点**                  | 自動で感度リスト生成・初回実行・安全性保証 |
| **対応する旧Verilog構文** | `always @(*)`                            |

---

要するに：

> 🔸 `always_comb` は、組み合わせ回路を安全・簡潔・確実に記述するための SystemVerilog の標準構文です。


## always_off

それでは、`always_comb`（組み合わせ回路）と `always_ff`（順序回路）の違いを、

**図解と具体例付きで**わかりやすく説明します。

---

## 🧩 1. `always_comb` と `always_ff` の基本的な違い

| 項目           | `always_comb`           | `always_ff`                          |
| -------------- | ------------------------- | -------------------------------------- |
| 回路の種類     | **組み合わせ回路**  | **順序回路（フリップフロップ）** |
| トリガー       | 信号の変化（自動検出）    | クロック立ち上がり／立ち下がり         |
| 記述目的       | 加算・比較・論理演算など  | レジスタ更新や状態保持                 |
| タイミング要素 | なし（常に即反映）        | あり（クロックごとに更新）             |
| 合成結果       | 論理ゲート                | フリップフロップ（D-FF）               |
| 旧Verilog相当  | `always @(*)`           | `always @(posedge clk)`              |
| 代入演算子     | `=`（ブロッキング代入） | `<=`（ノンブロッキング代入）         |

---

## ⚙️ 2. 図で見る動作の違い

### 🟢 `always_comb` の場合（組み合わせ回路）

```
a ──┐
    │
    │
    ├──→ 加算回路 → y
    │
b ──┘
```

* `a` または `b` が変わると即座に `y` が更新される。
* 記憶（保持）する要素はなし。
* 論理ゲートや加算器などの「純粋な処理」だけ。

```systemverilog
always_comb begin
    y = a + b;
end
```

---

### 🔵 `always_ff` の場合（順序回路）

```
        ┌──────────────┐
a ───→ D│              │Q──→ y
b ───→ +│   D-FF群     │
clk ───→ │              │
        └────▲─────┘
             │
          (posedge clk)
```

* 入力が変化してもすぐには出力に反映されない。
* **クロック立ち上がり**でのみ `y` が更新される。
* 出力が **保持される（レジスタ化される）** 。

```systemverilog
always_ff @(posedge clk) begin
    y <= a + b;
end
```

> 入力が変化してもすぐに出力に反映されない。
>
> クロック立ち上がりのみyが更新される。
>
> 出力が保持される。

## 🔍 3. 両者の動作タイミング比較

| 時間 | a | b | クロック(clk) | `always_comb`の出力 | `always_ff`の出力           |
| ---- | - | - | ------------- | --------------------- | ----------------------------- |
| t0   | 2 | 3 | 0             | 5                     | 5                             |
| t1   | 4 | 3 | 0             | 7                     | 5                             |
| t2   | 4 | 3 | 1 ↑          | 7                     | **7（クロックで更新）** |
| t3   | 5 | 3 | 0             | 8                     | 7                             |

🧠 **ポイント：**

* `always_comb` は入力が変わればすぐ反映。
* `always_ff` は「クロックが来るまで」出力が変わらない。

> always_combは入力が変化→すぐ変わる
>
> always_ffはクロックがくるまで出力が変わらない

## 🧱 4. 実際のコード例（組み合わせ＋順序）

4bitの乗算器を作って、結果をレジスタに保持する例です👇

```systemverilog
module mult4x4_reg (
    input  logic        clk,
    input  logic [3:0]  a, b,
    output logic [7:0]  product_reg
);
    logic [7:0] product_comb;

    // 組み合わせ回路（常に再計算）
    always_comb begin
        product_comb = a * b;
    end

    // 順序回路（クロックで更新）
    always_ff @(posedge clk) begin
        product_reg <= product_comb;
    end
endmodule
```

---

## 🧭 5. 両者の関係のまとめ図

```
     ┌────────────┐
a ─▶ │ always_comb │──▶ product_comb ─▶
b ─▶ │ (組み合わせ)│                   │
     └────────────┘                   ▼
                                   ┌──────────┐
                                   │always_ff │──▶ product_reg
                                   │(順序回路)│
                                   └──────────┘
                                         ▲
                                         │
                                      クロック
```

* `always_comb`：**計算する人**
* `always_ff`：**結果を覚える人**

という分担です。


## ✅ 6. まとめ

| 項目       | `always_comb` | `always_ff`      |
| ---------- | --------------- | ------------------ |
| 目的       | 組み合わせ回路  | 順序回路           |
| トリガー   | 信号の変化      | クロック           |
| 保持機能   | なし            | あり               |
| 代入演算子 | `=`           | `<=`             |
| 主な用途   | 加算・論理演算  | レジスタ・状態機械 |
| 合成結果   | ゲート          | フリップフロップ   |
