## ブロッキング代入とノンブロッキング代入

SystemVerilog（およびVerilog）における **`=`（ブロッキング代入）** と **`<=`（ノンブロッキング代入）** の違いは、**「実行順序」と「シミュレーションの意味（タイミング）」** にあります。

---

## 🔹 基本の違いまとめ

| 種類                           | 記号   | 名称                    | 主な用途                          | 実行タイミング                 | 特徴                                     |
| :----------------------------- | :----- | :---------------------- | :-------------------------------- | :----------------------------- | :--------------------------------------- |
| **ブロッキング代入**     | `=`  | blocking assignment     | 組み合わせ回路（`always_comb`） | 即時に実行される               | 次の文を実行する前に代入が完了する       |
| **ノンブロッキング代入** | `<=` | non-blocking assignment | 順序回路（`always_ff`）         | タイムステップの最後に一括更新 | 全ての右辺を評価した後に左辺が更新される |

> ブロッキング代入：即時に実行される
>
> ノンブロッキング代入：タイムステップの最後に一括更新する

## 🔸 例で理解する

### 【例1】ブロッキング代入（`=`）

```systemverilog
always_comb begin
    y = a;
    y = b;
end
```

この場合、`y` は最後の代入だけが有効になります。

→ `y = b;` の結果だけが出力されます。

→ 実行順に「ブロック（block）」されながら順次評価される、という意味です。

---

### 【例2】ノンブロッキング代入（`<=`）

```systemverilog
always_ff @(posedge clk) begin
    a <= b;
    b <= a;
end
```

この場合：

1. 右辺 (`b`, `a`) はクロックの立ち上がり時に**同時に評価**される
2. 左辺 (`a`, `b`) への代入は**全ての右辺評価が終わったあとに一斉に更新される**

したがって：

* `a` は「更新前の b」
* `b` は「更新前の a」

  というように**同時交換**が成立します。

---

## 🔹 よくある使い分けのルール

| 対象                                   | 使用する代入記号 | ブロックの種類  | 理由                             |
| :------------------------------------- | :--------------- | :-------------- | :------------------------------- |
| **組み合わせ回路**               | `=`            | `always_comb` | 即時評価で論理が自然に反映される |
| **フリップフロップ（順序回路）** | `<=`           | `always_ff`   | 並列更新を表現するため           |

---

## 🔸 あなたのコードでの該当箇所（修正版）

あなたのコード：

```systemverilog
if (sel)
    output <= a;
else
    output <= b;
```

➡ 組み合わせ回路（`always_comb`）なので

✅ **`<=` → `=` に変更するのが正しい** です。

修正版：

```systemverilog
always_comb begin
    if (sel)
        y = a;
    else
        y = b;
end
```

---

## 🔹 まとめ

| 観点       | `=`（ブロッキング） | `<=`（ノンブロッキング） |
| ---------- | --------------------- | -------------------------- |
| 意味       | すぐ代入される        | 後で一斉に代入される       |
| タイミング | 即時更新              | イベント終了時に更新       |
| 主な用途   | 組み合わせ回路        | フリップフロップ           |
| 使用場所   | `always_comb`       | `always_ff`              |
