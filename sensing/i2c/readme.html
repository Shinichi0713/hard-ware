目次

    電子システムは少しでも連携が必要になると、そのたびに基板同士を配線でつないでいく必要があり、システムが複雑になればなるほど、独立した基板を連携させる用途が多くなっていき、気づくと配線だらけとなってしまいます。 この配線だらけや、基盤ごとのデータ管理をシンプルに出来ないかということで開発された電子部品の通信規格にI2Cなるものがあります。

    本日はI2Cについて説明をしていきます。

    I2Cとは

    Inter-Integrated Circuit の略。フィリップス（現NXP）社が1982年に開発した、基板上のIC同士を2本の線で接続する同期式シリアル通信規格です。

    基本構成

    項目 内容
    配線数 2本（SDA：データ線、SCL：クロック線）
    接続方式 複数デバイスを同じバスに並列接続（マルチドロップ）
    アドレス指定 各デバイスに固有の7ビット（または10ビット）アドレスを割り当て
    速度 標準100kHz、高速400kHz、それ以上もあり
    性質 半二重（送受信を順番に行う）

    SPIとの違い

    マイコンでよく使われる通信規格としてSPIがあります。 双方を比較してみるとこんな特徴の違いがあります。

    項目 SPI I2C
    配線数 4本（MOSI/MISO/SCK/SS） 2本（SDA/SCL）
    デバイス数 SSピンを増やす必要あり アドレスで複数デバイスを同じ2本で共有
    速度 速い（MHzオーダー） やや遅い（kHz〜MHz）
    用途 高速・大量データ（ディスプレイ、SDカード、RFID） 複数センサーを少ない配線で接続（温度・湿度・気圧センサー、EEPROM）

    開発背景

    I2C（Inter-Integrated Circuit） は、1980年（実用化は1982年）にPhilips Semiconductors（現NXP） が開発しました。Wikipedia SparkFun

    開発の背景

    当時のテレビ・家電製品では、マイコンと周辺IC（チューナー、音量コントローラ、メモリなど）を接続するために、各ICごとに個別の配線が必要でした。これにより以下の問題が生じていました。

    • マイコンのピン数が逼迫する
    • PCB上の配線（トレース）が増え、基板が複雑・高価になる
    • 部品数が増え、製造コストが上昇する

    Philipsは、「2本の線だけで基板上の複数のICを繋げられないか」 という課題を解決するためにI2Cを設計しました。Total Phase NXP Application Note

    因みに、この複数のICという用途は過去説明したCANとも共通していて、通信線を専用線にせず、共通に使えるようにするということがいかに重要なテーマだったかということが分かる話だと考えています。

    設計の狙い

    目標 内容
    配線の最小化 データ線（SDA）とクロック線（SCL）の2本だけで通信
    複数デバイス接続 各ICにアドレスを割り当て、同じバスに並列接続
    コスト削減 基板面積と部品数を減らし、家電製品を安価に
    設計の標準化 自社製品間で共通のバスを使い、設計を効率化

    その後の展開

    • 1992年：初の公開仕様が発表され、400kHzのFast-modeと10ビットアドレスが追加
    • 当初はテレビ向けでしたが、現在はArduino・スマートフォン・PC・車載機器など、あらゆる電子機器で使われるデファクトスタンダードに

    主たる用途

    I2Cは、「配線が少なくて済み、複数デバイスを1本のバスで管理できる」 という特徴から、以下のような場面で広く使われています。

    1. センサとの通信（最も一般的）

    I2Cはセンサとマイコンの接続で最もよく使われます。理由は配線が2本（SDA・SCL）だけで済み、複数センサを並列接続できるからです。

    環境センサ

    センサ 測定対象 I2Cアドレス
    BME280 温度・湿度・気圧 0x76 / 0x77
    SHT30 温度・湿度 0x44 / 0x45
    LPS22HB 気圧 0x5C / 0x5D
    VEML6070 UV指数 0x38 / 0x39

    慣性・モーションセンサ

    センサ 測定対象 I2Cアドレス
    MPU6050/9250 加速度・ジャイロ（9軸） 0x68 / 0x69
    LSM6DS3 加速度・ジャイロ 0x6A / 0x6B
    LIS3DH 加速度 0x18 / 0x19

    光・距離センサ

    センサ 測定対象 I2Cアドレス
    VL53L0X レーザーToF距離 0x29
    TSL2561 照度 0x29 / 0x39 / 0x49
    APDS9960 近接・ジェスチャー・色 0x39

    2. ディスプレイ・UIデバイス

    小さな画面や入力デバイスもI2Cで接続されることが多いです。

    デバイス 用途 I2Cアドレス
    SSD1306 OLED 128×64ドット有機ELディスプレイ 0x3C / 0x3D
    LCD1602+I2Cバックパック 文字表示LCD（配線を2本に減らす） 0x27 / 0x3F
    CAP1188 8チャンネル静電容量タッチセンサ 0x28 / 0x29 / 0x2A / 0x2B
    PCF8574 GPIO拡張IC（リモート8bit I/O） 0x20〜0x27

    3. リアルタイムクロック（RTC）

    電源OFF時も時刻を保持するRTCモジュールはI2C接続が標準です。

    デバイス 用途 I2Cアドレス
    DS3231 高精度RTC（温度補償付き） 0x68
    DS1307 基本RTC 0x68
    PCF8523 低消費電力RTC 0x68

    注意: MPU6050やDS3231は同じ 0x68 アドレスを使うことがあるため、同じバスに接続する場合は片方のアドレスを変更する必要があります。

    4. EEPROM・メモリ

    設定値やキャリブレーションデータを保存する不揮発メモリ。

    デバイス 容量 I2Cアドレス
    AT24C32 32Kbit（4KB）EEPROM 0x50〜0x57
    AT24C256 256Kbit（32KB）EEPROM 0x50〜0x57

    センサのキャリブレーションデータや、デバイスの設定値を電源OFF後も保持する用途に使われます。

    5. 電源管理・モータードライバ

    デバイス 用途 I2Cアドレス
    INA219 電流・電圧・電力モニタ 0x40〜0x4F
    INA260 電流・電圧・電力モニタ（高精度） 0x40〜0x4F
    DRV8830 I2C制御モータードライバ 0x60〜0x63

    電池駆動のIoTデバイスで、消費電力をモニタリングする用途に便利です。

    6. I2Cが向く/向かない用途

    I2Cがこれらの場面で使われるのは、以下のメリットがあるからです。

    メリット 説明
    配線が少ない SDA・SCLの2本＋電源だけで通信可能
    複数デバイスを並列接続 同じ2本に複数台を繋げ、アドレスで識別
    標準的なライブラリ Arduinoの Wire.h、MicroPythonの machine.I2C など、ほぼ全マイコン対応
    低速〜中速で十分 センサのサンプリングレート（数Hz〜数百Hz）には十分な速度
    ACK応答で信頼性 各バイトごとにACK/NACKで受信確認ができる

    逆に、I2Cが選ばれない場面もあります。

    場面 向かない理由 代わりに使われるプロトコル
    高速データ転送 最大3.4Mbps（高速モード）でもSPIには遅い SPI
    長距離配線 数十cm以上だと信号劣化・容量の影響 RS-485, CAN
    1対1の単純通信 I2Cの複雑さが不要 UART
    リアルタイム性が厳しい バスアービトレーションによる遅延 SPI

    通信の仕組み

    I2Cの通信仕組みを、物理層からデータ転送の流れまで段階的に説明します。

    1. 物理層：2本の線で何を運ぶか

    I2CはSDA（データ線） とSCL（クロック線） の2本で通信します。

    信号線 役割
    SDA（Serial Data） データの送受信（双方向）
    SCL（Serial Clock） クロック信号（Masterが生成）

    オープンドレイン構成

    I2Cの各線はオープンドレイン（またはオープンコレクター） と呼ばれる特殊な出力方式です。

    各デバイスの内部
    │
    ├──→ トランジスタ（LOWを出力）
    │
    └──→ 抵抗（プルアップ）──→ VCC
    • LOW: トランジスタがON → 線をGNDに落とす
    • HIGH: トランジスタがOFF → プルアップ抵抗で線がVCCに引き上げられる

    なぜこの方式か: 複数デバイスが同じ線を共有していても、どれか1台がLOWにすると線全体がLOWになる。これが「ワイヤードAND」です。衝突しても壊れない設計になっています。

    プルアップ抵抗が必須

    VCC ──[4.7kΩ]──┬── SDA
               │
         ┌─────┴─────┐
         │  デバイスA  │
         │  デバイスB  │
         │  デバイスC  │
         └───────────┘
               │
              GND

    プルアップ抵抗がないと、HIGH状態が作れません。通常は 4.7kΩ（速度やデバイス数で調整）をSDAとSCLそれぞれに入れます。

    2. 直感的なアナロジー：教師と生徒の「挙手式」授業

    I2Cの通信を想像してください。 原則は通信の進行役がいて、進行役の指示に基づき、必要な配下センサから情報を集めていくという仕組みです。

    • 教師（Master）: 授業の進行役。誰に質問するか決め、時計（クロック）で合図を出す
    • 生徒たち（Slaves）: 各々に出席番号（I2Cアドレス）がある。教師が指名するまで黙っている
    • 黒板（SDA線）: 教師も生徒も同じ黒板に書く。ただし、教師が「次は出席番号5番」と言うまで、誰も勝手に書かない

    3. 通信の基本単位：START・STOP・データビット

    START条件（通信開始）

    SCL:  ──────┐   ┌───┐   ┌───┐   ┌───
              └───┘   └───┘   └───┘

SDA:  ─────────┐
               └───────────────
               ↑
            START
               （SCLがHIGHの間にSDAがHIGH→LOWに変化）

    SCLがHIGHの間に、SDAがHIGHからLOWに落ちると、全デバイスに「通信が始まるぞ」と合図されます。

    STOP条件（通信終了）

    SCL:  ────┐   ┌───┐   ┌───┐   ┌──────
          └───┘   └───┘   └───┘

SDA:  ───────┐                   ┌────
             └───────────────────┘
                                 ↑
                                STOP
               （SCLがHIGHの間にSDAがLOW→HIGHに変化）

    SCLがHIGHの間に、SDAがLOWからHIGHに上がると、通信終了の合図です。

    データビットの転送

    SCL:  ────┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
          └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘
              ↑       ↑       ↑       ↑       ↑       ↑       ↑       ↑
           サンプル  サンプル  サンプル  サンプル  サンプル  サンプル  サンプル  サンプル

SDA:  ────┐   ┌───────┐   ┌───────────────┐   ┌───────┐   ┌───────────────
          └───┘       └───┘               └───┘       └───┘
           D7          D6          D5          D4          D3...
    • SCLがLOWの間: SDAの値を変えてもよい（データ準備）
    • SCLがHIGHの間: SDAの値が確定し、相手が読み取る（データ確定）

    1クロックサイクルで1ビット転送。1バイト（8ビット）送るには8クロック必要です。

    4. 完全な通信シーケンス

    書き込み（Master → Slave）

    MasterがSlaveのレジスタにデータを書き込む流れ
=================================================

[START] → [Slaveアドレス(7bit) + R/W(0=Write)] → [ACK] → [レジスタアドレス] → [ACK]
  → [データ1] → [ACK] → [データ2] → [ACK] → ... → [STOP]

    具体例: BME280のコントロールレジスタ（0xF4）に値0x27を書き込む

    ステップ SDA上の内容 説明
    1 START 通信開始
    2 0xEC（= 0x76 << 1 + 0） Slaveアドレス(0x76) + Write(0)
    3 ACK（Slaveから） 「私が0x76です。受け取りました」
    4 0xF4 書き込むレジスタのアドレス
    5 ACK（Slaveから） 「レジスタアドレス受け取りました」
    6 0x27 書き込むデータ
    7 ACK（Slaveから） 「データ受け取りました」
    8 STOP 通信終了

    読み込み（Slave → Master）

    読み込みは 「書き込みでレジスタを指定」→「読み込みでデータ取得」 の2段階です。

    MasterがSlaveのレジスタからデータを読む流れ
============================================

[START] → [Slaveアドレス + W(0)] → [ACK] → [読み出すレジスタアドレス] → [ACK]
  → [Repeated START] → [Slaveアドレス + R(1)] → [ACK]
  → [データ1] → [ACK(Master)] → [データ2] → [ACK(Master)] → ... → [データN] → [NACK(Master)] → [STOP]

    具体例: BME280の温度データレジスタ（0xFA〜0xFC）を読む

    ステップ SDA上の内容 説明
    1 START 通信開始
    2 0xEC（0x76 + W） 「0x76に書き込みたい」
    3 ACK 「了解」
    4 0xFA 「温度データの先頭アドレスを指定」
    5 ACK 「了解」
    6 Repeated START 「次は読み込みに切り替える」
    7 0xED（0x76 + R） 「0x76から読み込みたい」
    8 ACK 「了解。データを送ります」
    9 データバイト1 Slaveが温度MSBを送信
    10 ACK（Master） 「次も送って」
    11 データバイト2 Slaveが温度LSBを送信
    12 ACK（Master） 「次も送って」
    13 データバイト3 Slaveが温度XLSBを送信
    14 NACK（Master） 「もう十分。これ以上送らないで」
    15 STOP 通信終了

    5. ACKとNACKの仕組み

    送信した側が、受信した側からの応答を待ちます。

    送信側（8ビット送信後）          受信側
    │                              │
    │  ←──── SDAをLOWにする ────  │  ACK（「受け取った」）
    │                              │
    │  ←──── SDAをHIGHのまま ───  │  NACK（「受け取れなかった」）
    応答 意味
    ACK（SDAをLOWに引く） 「データを正しく受信した。次を送って」
    NACK（SDAをHIGHのまま） 「データを受信できなかった、またはもう不要」

    6. クロックストレッチ（Clock Stretching）

    Slave側が処理に時間がかかる場合、SCLをLOWのまま保持してMasterを待たせることができます。

    SCL(Master):  ──┐   ┌───┐   ┌───────  ← SlaveがSCLをLOWに引き延ばす
               └───┘   └───┘
SCL(実際):    ──┐   ┌───┐   ┌──────────
               └───┘   └───┘   ↑
                               SlaveがSCLをLOWに保持
                               （処理完了までMasterを待たせる）

    BME280などのセンサは、測定モードに入れてからデータが準備できるまで、クロックストレッチでMasterを待たせることがあります。

    7. マルチマスターとアービトレーション

    I2Cは理論上、複数のMasterが同じバスに存在できます。

    アービトレーション（衝突解決）

    2台のMasterが同時に通信を始めた場合：

    Master A:  SDAに 1(HIGH) を出力しようとする
Master B:  SDAに 0(LOW) を出力しようとする

結果: SDAはLOWになる（オープンドレインのワイヤードAND）
       Master Aは「自分がHIGHを出したのにSDAがLOWになった」と検知
       → Master Aは自分が負けたと判断し、通信を中断
       → Master Bが勝利し、通信を継続

    「LOWを出力した方が勝つ」 という単純なルールで、衝突を壊れることなく解決できます。

    8. まとめ：I2C通信の全体像

    全体像は以下の絵のようになります。

    総括

    I2Cは、基板上のIC同士を2本の線（SDA・SCL）で接続し、各ICに割り当てたアドレスで通信相手を選んでデータをやり取りする同期型シリアル通信規格です。Philips（現NXP）が1982年に、テレビ・家電の基板配線を減らすために開発しました。

    要点

    • 解決した問題: マイコンと周辺ICを個別配線で繋ぐとピン数・基板面積・コストが増大する問題
    • 基本構成: SDA（データ）とSCL（クロック）の2本で複数デバイスを並列接続。各デバイスは固有の7ビットアドレスを持つ
    • SPIとの違い: I2Cは配線2本で複数デバイスをアドレスで管理できるが、SPIは4本＋CSピンがデバイスごとに必要。I2Cは低速、SPIは高速
    • 用途: 温度・湿度・気圧センサ、加速度・ジャイロ、OLEDディスプレイ、RTC、EEPROM、電源モニタなど
    • 通信の流れ: START条件で開始 → Slaveアドレス＋R/Wを送信 → ACKで応答確認 → データバイトを送受信 → STOP条件で終了
    • 特徴的な仕組み: オープンドレイン＋プルアップの「ワイヤードAND」構造、ACK/NACKによる受信確認、クロックストレッチ、マルチマスター時のアービトレーション

    I2Cは、基板上の複数のICを2本の線で並列接続し、アドレス指定で個別に通信する、配線を最小化した同期型シリアルバス規格です。
