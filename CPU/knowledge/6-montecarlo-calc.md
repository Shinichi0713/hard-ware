# モンテカルロ試行回数

 目的（`torch.allclose`で「等価」とみなせるかを評価）に合わせて**モンテカルロ試行回数（サンプル数）の決め方**を統計的に整理し、実務で使える目安と実装例をお渡しします。

ポイントは次のとおりです：

* 「等価」とみなす判断は**確率的**なもの（ランダム入力で一致する割合）なので、**信頼区間（confidence interval）**や**検出力（power）**を基準に必要サンプル数を決めます。
* まずは**パイロット試行（小数：1k程度）**で失敗率や差の分布を見てから本数を決めるのが効率的です。
* また `torch.allclose` はテンソル全体のブール判定なので、 **全要素が条件を満たす割合** （＝成功率）や、**最大差 / 要素差の分布**も同時に観察することを強く推奨します。

以下、数学的な導出 → 実用的な推奨 → 具体的なコード例 の順で説明します。

---

## 1) 概念とサンプル数決定の考え方（成功/失敗モデル）

各ランダム入力に対して `torch.allclose` が `True` か `False` かを観測すると、これは **ベルヌーイ試行** （成功確率 (p)）になります。

我々が興味あるのは例えば：

* 「失敗率 (p_\text{fail}) が 0.1% 以下であることを 95% 信頼度で確認したい」

  などの命題です。

### 二項分布に基づく必要サンプル数（正規近似）

95% 信頼区間（片側あるいは両側）で許容誤差 (e)（＝信頼区間の半幅）を得たいとき、正規近似を使うと：

[

n \approx \frac{z^2 , p(1-p)}{e^2}

]

* (z) は信頼係数（95% → 1.96、99% → 2.576）
* (p) は予想される失敗確率（不明な場合は保守的に 0.5 を使う）
* (e) は許容する誤差（絶対値）

 **注意** ：失敗率が極小（例 (p<0.01)）の場合、正規近似はあまり良くないので Wilson 区間などを使うか、上式で保守的に計算しておくと良いです。

### 実用例（95% 信頼, z=1.96）

* 保守（p=0.5）かつ許容誤差 (e=1%) →

  (n \approx 0.9604 / 0.01^2 = 9{,}604)
* より小さい誤差 (e=0.5%) → (n \approx 38{,}416)
* 小さい失敗率を検出したい（例 p ≈ 0.1% = 0.001）、許容誤差 (e=0.05% = 0.0005)：

  (n \approx \frac{1.96^2 \cdot 0.001\cdot0.999}{(0.0005)^2} \approx 15{,}352)

表にまとめると（95%）:

| 目標（許容誤差 e） | 保守（p=0.5）の n | 小 p=0.001 の場合の n |
| -----------------: | ----------------: | --------------------: |
|    e = 1.0% (0.01) |              9.6k |           ≈96k（※） |
|   e = 0.5% (0.005) |             38.4k |          ≈384k（※） |
|   e = 0.1% (0.001) |            960.4k |          ≈9.6M（※） |

（※：小 p 用には別計算が必要。上の右欄は p=0.001 を使い e同値で計算した場合の目安。実務では pが小さい場合、必要 nが急増します）

---

## 2) 別の観点：誤差（差の実数値）の平均を推定したい場合

もし「出力差（例えば要素ごとの差の絶対値）の平均 (\mu) を ±Δ の精度で推定したい」なら、平均値のサンプル数は

[

n \approx \left(\frac{z \sigma}{\Delta}\right)^2

]

* (\sigma) は差の標準偏差（不明ならパイロットで推定）
* (\Delta) は絶対誤差許容（例：平均差 ±1e-4）
* z は同じく信頼係数

この場合は **パイロット試行** （例 1000 サンプル）で (\sigma) を求め、上式で必要 n を算出するのが実務的です。

---

## 3) あなたの目的（`torch.allclose` を使う）への実践的推奨

1. **パイロット 1,000 回**
   * まず 1,000 サンプル（ランダム入力）で `allclose` の成功率 ( \hat p ) と失敗時の差の分布（最大差、平均差、分位点）を計測。
   * ほとんどの現場でこの段階で問題ないかどうかの判断がつきます。
2. **必要サンプル数の算出**
   * パイロットの ( \hat p ) を使って、上の二項分布式で必要な n を計算する。
   * もし (\hat p) がゼロ（失敗無し）なら、 **上限を推定する方法** ：0 failures in n0 trials gives an upper 95% CI for p ≈ 3/n0（Poisson 計算近似）。

     例：n0 = 1000 で 0 failures → 上限 p ≈ 3/1000 = 0.003 (0.3%)（95%信頼）
3. **推奨レンジ（実務目安）**
   * **軽いチェック** ：1k ～ 10k（開発初期）
   * **実運用での検証** ：10k ～ 100k（多くのケースで十分）
   * **高信頼（失敗率 < 1e-4 を確認したい等）** ：100k ～ 1M（計算コストと相談）
4. **分布をカバーする工夫**
   * 単純な一様ランダムだけでなく、**境界値（大きな入力やゼロ付近）・高分散領域・特定チャネル組合せ**をストラティファイド（層別）でサンプリングする。これにより「希な失敗」が見つかりやすくなります。
   * 重要：単にランダムで「見つからない」からと言って本当に安全とは限らない（カバレッジ問題）。
5. **`torch.allclose` の設定確認**
   * `rtol` / `atol` の設定が判定に直結します。どの許容値で「等価」とするかを明文化しておく（例 `rtol=1e-05, atol=1e-08` 等）。
   * また `allclose` は **テンソルの全要素が条件を満たすか** を返すため、要素差の分布（最大差、% of elements exceeding tol）もログに残すと安心です。

---

## 4) 実践的な Python (PyTorch) スクリプト例

以下は「パイロット → 必要 n 計算 → 追加検証を行う」簡易ワークフローのサンプルです。`allclose` を繰り返し実行して失敗率と Wilson 信頼区間を得ます。

```python
import torch
import math
from statsmodels.stats.proportion import proportion_confint  # pip install statsmodels
import numpy as np

def montecarlo_compare(funcA, funcB, sample_input_fn, n_samples=1000, rtol=1e-5, atol=1e-8, batch=1):
    failures = 0
    diffs = []
    for i in range(n_samples):
        x = sample_input_fn()
        yA = funcA(x)
        yB = funcB(x)
        ok = torch.allclose(yA, yB, rtol=rtol, atol=atol)
        if not ok:
            failures += 1
            diffs.append((yA - yB).abs().max().item())
    p_hat = failures / n_samples
    # 95% CI (Wilson)
    lower, upper = proportion_confint(failures, n_samples, method='wilson')
    stats = {
        'n': n_samples,
        'failures': failures,
        'p_hat': p_hat,
        'p_CI_95': (lower, upper),
        'max_diff_observed': max(diffs) if diffs else 0.0,
        'mean_diff_if_any': float(np.mean(diffs)) if diffs else 0.0
    }
    return stats

# 例: サンプル入力生成関数
def sample_input():
    # ここはユーザの入力分布に合わせる
    # 例: 200x64x64 のfloatテンソル -100..100 の一様分布
    return (torch.rand(1,200,64,64)*200 - 100).float()

# 使い方（パイロット）
# stats = montecarlo_compare(funcA, funcB, sample_input, n_samples=1000)
# print(stats)
```

* `proportion_confint` の Wilson 法で95% 信頼区間を出しています。
* `p_hat=0`（失敗ゼロ）の場合、Wilson下限が0でも上限が `~3/n`（Poisson近似）に相当することに注意してください。

---

## 5) 最後に：実務的アドバイス（要約）

* **まず 1k のパイロット**で `p_hat` と差の分布を把握。
* 小さな `p_hat`（例えば <0.001）で「高信頼」を欲するなら **数万（10k〜100k）** の試行を推奨。
* もし「失敗率がほぼ 0（ゼロ）」を立証したい場合、 **ゼロ失敗で n=3000 なら上限 ≈0.001（95%）** 、**n=30k なら上限 ≈1e-4** の目安。
  * 近似：上限 ≈ 3 / n（95% Poisson upper bound）
* **入力分布のカバレッジ** （境界・異常値・高振幅）を忘れない。ランダムだけでなく層別サンプリングを行うこと。
* `torch.allclose` の `rtol/atol` を仕様として固定しておき、その値で評価すること。

---

### 🌿 1. 統計学における「信頼度」

統計学では、**信頼度（confidence level）** は **区間推定における確からしさ** を表します。

#### 🔹 定義

> 信頼度とは、「母集団の真の値が、信頼区間に含まれる確率」のこと。

たとえば：

* 95%の信頼度で母平均を推定する、というのは

  →「無数に標本を取り直したとき、そのうち95%の信頼区間は真の平均値を含む」という意味です。

  ※個別の1回の区間に対して「確率95%で含まれる」という意味ではありません。

#### 🔹 数式イメージ

[

P(\mu \in [\bar{x} - z_{\alpha/2}\frac{\sigma}{\sqrt{n}}, \bar{x} + z_{\alpha/2}\frac{\sigma}{\sqrt{n}}]) = 1 - \alpha

]

ここで、( 1 - \alpha ) が信頼度です（例：0.95）。

---

### ⚙️ 2. 機械学習・深層学習における「信頼度」

ニューラルネットワークの出力（特に分類タスク）では、**信頼度（confidence）** は「モデルが予測にどれだけ確信を持っているか」を示す値です。

#### 🔹 定義

> 信頼度 ＝ 出力確率（softmaxなど）の最大値。

たとえば、モデルが画像を分類して

```
cat: 0.9, dog: 0.05, car: 0.05
```

のような出力をした場合、信頼度は 0.9 です。

ただし、この「確率」は理論的な真の確率ではなく、 **モデルの主観的な確信度** （＝キャリブレーションが必要なことも多い）です。

---

### 🧮 3. モンテカルロシミュレーションにおける信頼度

あなたが行いたいような  **モンテカルロシミュレーション** （関数AとBの出力が等価かを確かめる）では、信頼度は「推定結果の確からしさ」の指標です。

#### 🔹 定義

> 信頼度とは、シミュレーションで得られた統計的推定値（平均、分散、確率など）が、真の値に近いとみなせる程度を表すもの。

#### 🔹 実際の意味

たとえば、「2つの関数が等価とみなせる確率を95%信頼度で評価したい」と言うときは、

モンテカルロ試行を増やして、結果の**信頼区間の幅**を小さくするように調整します。

## 🧮 試行回数の目安（信頼度 vs. 回数）

信頼度 (1-\alpha)、誤差範囲 (E)、母標準偏差を (\sigma) とすると

必要な試行回数 (n) は概ね：

[

n \approx \left(\frac{z_{\alpha/2} \cdot \sigma}{E}\right)^2

]

ここで：

* (z_{\alpha/2})：信頼度に対応する標準正規分布の値

  （例：95% → 1.96、99% → 2.58）
* (E)：許容誤差（例：1e−4など）

たとえば：

* 95%信頼度、誤差1e−4、標準偏差1e−3なら

  [

  n ≈ \left(\frac{1.96 \times 10^{-3}}{10^{-4}}\right)^2 ≈ 384

  ]

  →  **おおよそ400回のシミュレーションで十分** 。

# 等価な基準


非常に本質的で良い質問です。

`torch.allclose` の `atol`（絶対誤差）と `rtol`（相対誤差）を **「数学的に妥当な値」** に設定するには、

単に経験則で決めるのではなく、

**数値誤差の理論限界（IEEE 754浮動小数点誤差の蓄積）** を踏まえて考えるのが最も理にかなっています。

以下では、**理論的背景 → 実際のCNN計算の誤差伝搬 → 設定指針** の順に説明します。

---

## 🧮 1. IEEE754の浮動小数点誤差の基本

### 🔹 浮動小数点の丸め誤差（ULP単位）

* 32bit浮動小数点（`float32`）の仮数部は23ビット。

  → 有効桁数はおおよそ  **7桁** 。
* したがって、

  数値 ( x ) に対して丸め誤差はおおよそ：

  [

  \varepsilon_{\text{float32}}(x) ≈ 10^{-7} \times |x|

  ]
* 64bit（`float64`）の場合は有効桁が約15桁で、

  [

  \varepsilon_{\text{float64}}(x) ≈ 10^{-15} \times |x|

  ]

---

## ⚙️ 2. ニューラルネットワークにおける誤差の伝搬

CNNやMLPのような線形演算（行列積など）では、

各層での誤差は **加算・乗算誤差の累積** で増幅します。

### 典型的な近似

誤差伝搬を簡単に見積もると：

[

\delta_{\text{out}} ≈ n_{\text{ops}} \cdot \varepsilon_{\text{float32}}

]

ここで (n_{\text{ops}}) は計算回数（積和演算の回数）です。

たとえば：

* 畳み込み1層で、入力64×64×200、カーネル3×3なら

  (n_{\text{ops}} ≈ 64×64×200×9 ≈ 7.3×10^7)
* 誤差見積もり：

  [

  \delta_{\text{out}} ≈ 7.3×10^7 × 10^{-7} = 7.3

  ]

  → そのままだと大きすぎるが、実際には符号が打ち消し合うため、

  RMS的にはおよそ **√nのオーダー** に減衰します：

  [

  \delta_{\text{out,rms}} ≈ \sqrt{7×10^7} × 10^{-7} ≈ 2.6×10^{-4}

  ]

  →  **float32では1e−4程度の誤差が自然レベル** 。

---

## 📐 3. torch.allclose の数学的な意味

`torch.allclose(a, b, rtol, atol)` は次の条件をチェックします：

[

|a_i - b_i| \le \text{atol} + \text{rtol} \cdot |b_i|

]

つまり：

* **`atol`** は「スケールが小さい値の絶対許容誤差」
* **`rtol`** は「値の大きさに比例する相対誤差」

---

## ✅ 4. 実用かつ数学的に妥当な設定指針

あなたのケース（入力スケール ±100、float32、CNN 1層）では：

| パラメータ | 意味     | 推奨値             | 理由                                                       |
| ---------- | -------- | ------------------ | ---------------------------------------------------------- |
| `rtol`   | 相対誤差 | `1e-4`〜`1e-5` | float32の理論精度（1e−7）に対して演算蓄積を考慮した妥当値 |
| `atol`   | 絶対誤差 | `1e-3`〜`1e-4` | 出力スケール100に対し、誤差5e−4観測ならこの程度が合理的   |

このとき `torch.allclose(a, b, rtol=1e-4, atol=1e-3)` で

観測誤差5e−4は「数学的にも実装上も等価」と判断できます。

---

## 📊 5. より厳密に求めたい場合

誤差の理論限界から動的に `atol` を決めることも可能です：

```python
eps = torch.finfo(torch.float32).eps  # 1.192e-7
rtol = 10 * eps**0.5                 # 約1e-3.5 = 3e-4
atol = rtol * input.abs().max()      # 入力スケールに比例
```

これにより、「浮動小数点精度 × 入力スケール × 安全マージン」を考慮した

“理論的に妥当な” `allclose` 判定が得られます。

| 要素            | 値（目安）                                     | 根拠                     |
| --------------- | ---------------------------------------------- | ------------------------ |
| データ型        | float32                                        | 通常のNN計算             |
| 入力スケール    | ±100                                          | 指定条件                 |
| 観測誤差        | ≈5e−4                                        | 実測値                   |
| 妥当な `rtol` | **1e−4**                                | 相対誤差の自然範囲       |
| 妥当な `atol` | **1e−3**                                | 絶対誤差の安全範囲       |
| 判定式          | `torch.allclose(a, b, rtol=1e-4, atol=1e-3)` | 数学的にも実装的にも適切 |
